# MCU Template for RP2350 Microcontrollers (Raspberry Pi Pico 2)
## Overview
The RP2350 from Raspberry Pi is a 32-bit microcontroller with two Arm® Cortex®-M33 cores (with single precision FPU, DSP instructions and TrustZone) running at up to 150MHz. Alternatively, the chip can run two Hazard3 RISC-V cores. It has 520KB of on-chip SRAM, 8KB of OTP memory, no internal flash (except RP2354) and executes code from an external QSPI flash memory (execute in place, XIP, with 16KB cache). The I/O supply voltage is 1.8V to 3.3V, the core voltage is generated by an internal switching regulator. The chip has the following peripherals:
- two UARTs, two SPI controllers and two I2C controllers
- 24 PWM channels (12 slices with two outputs each, 8 slices on pins of the RP2350A)
- a 12-bit ADC (500ksps, 4 inputs on RP2350A, 8 inputs on RP2350B, and internal temperature sensor)
- three programmable I/O blocks (PIO) with 4 state machines each, which can implement almost any digital interface (e.g. WS2812, I2S, VGA, additional UARTs)
- a high-speed serial transmit interface (HSTX, e.g. for DVI)
- a USB 1.1 full-speed controller with PHY (device and host mode)
- two 64-bit microsecond timers with 4 alarms each, an always-on timer (AON, in the power manager) and a watchdog
- a 16-channel DMA controller, interpolators, a true random number generator (TRNG) and a SHA-256 accelerator
- a crystal oscillator (XOSC), a ring oscillator (ROSC), a low power oscillator (LPOSC) and two PLLs
- security features: secure boot, OTP keys, glitch detectors, access control

The boot ROM contains a USB bootloader (BOOTSEL mode), which appears as a mass storage device (RP2350 drive) for UF2 files and as a PICOBOOT interface (used by rpprog and picotool). It is started by holding the BOOTSEL button (flash chip select pulled low) during reset or power-up, or by the firmware. In contrast to the RP2040, the RP2350 does not need a second stage bootloader: the boot ROM sets up the flash interface itself and starts the firmware, if it finds a valid image definition block (IMAGE_DEF) within the first 4KB of the flash.

This template is a lightweight starting point for bare-metal firmware development in C without the Raspberry Pi Pico SDK, any HAL or IDE. It contains:
- a makefile
- linker scripts
- an image definition block, startup code and system configuration
- basic GPIO, pin interrupt and ADC functions
- an example program

Optional libraries for the internal peripherals are also included. The template supports the Arm cores in secure mode (the default after reset), RISC-V and the TrustZone non-secure state are not covered.

## Supported Microcontrollers and Boards

| Device / Board | Flash | Crystal | LED | Linker Script |
|:-|-:|:-:|:-:|:-|
| Raspberry Pi Pico 2 | 4MB (W25Q32RV) | 12MHz | GP25 | ld/rp2350_4mb.ld |
| Raspberry Pi Pico 2 W | 4MB (W25Q32RV) | 12MHz | (WiFi chip) | ld/rp2350_4mb.ld |
| RP2354A (stacked flash) | 2MB | 12MHz | - | ld/rp2350_2mb.ld |
| Other boards with RP2350A | 2..16MB | 12MHz | - | ld/rp2350_<size>.ld |

The flash size is selected in the *makefile* (`LDSCRIPT`). The boot ROM detects the read mode of the flash chip automatically, so no flash-specific boot code is required. The template assumes a 12MHz crystal (`XOSC_VALUE` in *rp2350.h*), which is used by all common boards. Check the documentation of your board for the flash size and the LED pin. The RP2350B (QFN80, 48 GPIOs) can be used as well, but the pin designators and GPIO functions of the template only cover GP0..GP29.

Common features:
- Dual Arm® Cortex®-M33 cores with FPU, up to 150MHz (overclocking is possible, but not supported by the template)
- 520KB SRAM in ten banks (8 x 64KB striped, 2 x 4KB), 32KB boot ROM, 8KB OTP, 16KB XIP cache
- 30 GPIOs (GP0..GP29, GP26..GP29 with ADC) on RP2350A, dedicated USB pins (USB_DP/USB_DM), serial wire debug (SWCLK, SWDIO)
- 64-bit unique chip ID in the OTP (`ESIG_UID64`, used as board ID)

The Raspberry Pi Pico 2 has the same form factor and pinout as the Raspberry Pi Pico: a 3-pin debug header (SWCLK, GND, SWDIO), the BOOTSEL button and the RUN pin (pin 30, reset when pulled low). The ADC reference is the 3.3V supply (ADC_VREF on pin 35).

## Template Structure

| Path | Description |
|:-|:-|
| template/makefile | Makefile for compiling and uploading (GCC ARM toolchain, rpprog, OpenOCD) |
| template/ld/ | Linker scripts for 2/4/8/16MB flash (vector table at 0x10000000, IMAGE_DEF block, SRAM 520KB) |
| template/src/main.c | Example program (blinking LED on GP25) |
| template/src/system.c/h | IMAGE_DEF block, startup code, vector table, pin designators, clock (XOSC, PLLs, tick generators), RTC (calendar on the AON timer), delay, watchdog, sleep/dormant, reset, bootloader, boot ROM, CRC, DMA and interrupt functions |
| template/src/gpio.h | GPIO, pin interrupt and ADC functions (incl. temperature sensor) |
| template/src/rp2350.h | Register definitions (CMSIS core Cortex-M33 and RP2350 peripherals, generated from the SVD file of the Pico SDK) |
| libraries/ | Optional libraries for internal peripherals (see below) |
| datasheet/ | Links to the datasheets |

## Libraries
The *libraries* folder contains optional libraries for the internal peripherals. To use a library, copy the corresponding *.c* and *.h* files into the *src* folder of the template and include the header file in your program. Parameters such as pins, baud rate or clock rate can be set in the parameter section at the beginning of the respective header file. Libraries that use the same peripheral (e.g. *uart* and *debug_serial* on the same UART, or *spi* and *spi_dma*) must not be used at the same time.

| Library | Description |
|:-|:-|
| debug_serial | Serial debug output (UART, TX only) with simple printf, for debugging |
| flash | Flash memory functions (via boot ROM and QMI direct mode): erase sectors, write pages/words, user data at the end of the flash, unique ID and JEDEC ID of the flash chip |
| i2c | I2C master functions (I2C0/I2C1, polling) |
| i2c_soft | Software I2C master (bit-banging) on any pins |
| millis | Millisecond and microsecond counter using the 64-bit TIMER0 (no interrupt) |
| multicore | Start functions on core 1, inter-core FIFO and spinlocks (software spinlocks because of erratum RP2350-E2) |
| neo_pio | NeoPixel (WS2812) control using a PIO state machine (any pin) |
| pio | PIO functions: load programs, configure and control state machines, instruction encoding (PIO0..PIO2) |
| print | Print functions (printf, numbers, strings) for the serial and other libraries |
| pwm | PWM outputs on any pin (8 slices, 16 channels) |
| spi | SPI master functions (SPI0/SPI1) |
| spi_dma | SPI master functions with DMA (background transfers of buffers) |
| spi_soft | Software SPI master (bit-banging) on any pins |
| timer | Periodic timer interrupt (TIMER0 alarm 0) |
| uart | Basic UART functions (UART0/UART1, polling, no buffer, incl. UART_AUX pins) |
| uart2 | Second UART (copy of uart with prefix `UART2_`, default UART1) |
| usb/usb_cdc | USB CDC (virtual serial port), with 1200 baud touch to enter the USB bootloader |
| usb/hid_keyboard | USB HID keyboard |
| usb/hid_mouse | USB HID mouse |
| usb/hid_consumer | USB HID consumer control (media keys) |
| usb/hid_composite | USB HID composite device (keyboard, mouse and consumer control) |

The USB libraries consist of several files (all files of the respective folder must be copied into the *src* folder). The USB device descriptors and strings are set in *config.h*. The USB libraries have the same structure and API as the USB libraries of the RP2040, ATSAMD21, CH32X035 and ATSAMD11 templates (device mode only): only the USB handler (*usb_handler.c*) is specific to the RP2040/RP2350, the class drivers are identical. The USB controller is clocked with 48MHz by PLL_USB, independent of `F_CPU`. Note that the VID/PID in *config.h* are shared IDs for testing purposes only.

The functions of the clock system, RTC, watchdog, sleep modes, DMA, CRC (DMA sniffer) and boot ROM are part of *system.h*. The GPIO, pin interrupts and the ADC are part of *gpio.h*. HSTX, TRNG, SHA-256, the interpolators, the OTP programming, the security features (TrustZone, secure boot), the low power states of the power manager, the USB host mode and PIO programs other than WS2812 are not covered by the libraries, but can be used directly via the register definitions in *rp2350.h* (and the *pio* library).

## Compiling Firmware
To use the *makefile*, some additional software components must be installed to set up the toolchain.

### Install GCC Toolchain for Compiling
```
sudo apt install build-essential gcc-arm-none-eabi libnewlib-arm-none-eabi
```
The toolchain must support the Cortex-M33 (GCC 8 or newer).

### Install Python3 and Programming Tools
```
sudo apt install python3 python3-pip
pip install rpprog
```
[rpprog](https://github.com/wagiminator/MCU-Flash-Tools) uploads the binary file via the PICOBOOT interface of the USB bootloader (no drive has to be mounted). On newer Linux distributions, `pipx install rpprog` or a virtual environment may be required. To use rpprog without root privileges, grant access permissions to the USB bootloader:
```
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="2e8a", ATTR{idProduct}=="000f", MODE="666"' | sudo tee /etc/udev/rules.d/99-rp2350.rules
sudo udevadm control --reload-rules
```

### Compiling/Uploading
Edit the *makefile* according to the needs of the project (e.g. `F_CPU`, `LDSCRIPT`). Use one of the following commands inside the *template* folder to compile/upload:

```
make all       compile and build <firmware>.elf/.bin/.hex/.asm
make hex       compile and build <firmware>.hex
make asm       compile and disassemble to <firmware>.asm
make bin       compile and build <firmware>.bin
make flash     compile and upload to MCU (USB bootloader, rpprog)
make flash-swd compile and upload to MCU via SWD (CMSIS-DAP, OpenOCD)
make reboot    reboot MCU into USB bootloader (only if usb_cdc is used)
make clean     remove all build files
```

Supported values for `F_CPU`: 12MHz (crystal oscillator without PLL) and 16MHz to 150MHz, if the frequency can be generated exactly by the PLL, e.g. 150 (default), 144, 133, 125, 120, 100, 96, 72, 64, 50, 48, 36, 32 and 24MHz.

The code is compiled for the Cortex-M33 with the single precision FPU (`-mfloat-abi=softfp -mfpu=fpv5-sp-d16`). The FPU is enabled in the startup code (`SYS_FPU_EN` in *system.h*). If the FPU is disabled, the floating point options must also be removed from `CPUARCH` in the *makefile*.

## Uploading Firmware
### Via USB Bootloader (BOOTSEL Mode)
Hold the BOOTSEL button while connecting the board to the PC via USB (or while pressing the RESET/RUN button, if available), then release the button. The RP2350 appears as a mass storage device named RP2350 and as a PICOBOOT device.
- **rpprog**: `make flash` uploads the binary file with [rpprog](https://github.com/wagiminator/MCU-Flash-Tools) (`rpprog -b -f bin/<firmware>.bin`). The firmware is written, verified and started. rpprog also accepts UF2, HEX and ELF files.
- **From the firmware**: `BOOT_now()` restarts the RP2350 into the USB bootloader. With the *usb_cdc* library, the bootloader is also entered when the host opens the serial port with 1200 baud and closes it again. `rpprog -b` does this automatically (`make flash`, or `make reboot` to only restart into the bootloader), so the BOOTSEL button is not needed for further uploads.
- **Drag and drop**: The RP2350 drive only accepts UF2 files. If needed, the binary file can be converted with picotool, e.g. `picotool uf2 convert bin/<firmware>.bin <firmware>.uf2 -o 0x10000000 --family rp2350-arm-s`, and then copied to the drive.

### Via Serial Wire Debug Interface (SWD)
Connect an SWD programmer that supports the RP2350 (e.g. Raspberry Pi Debug Probe) to the SWCLK, SWDIO and GND pins of the debug header. `make flash-swd` uploads the firmware via [OpenOCD](https://openocd.org/) (version with RP2350 support, e.g. from the Raspberry Pi fork, target *rp2350.cfg*).

```
SWD Programmer      RP2350 / Pico 2
+------------+      +-------------+
|       SWCLK| ---> |SWCLK        |
|       SWDIO| <--> |SWDIO        |
|         GND| ---> |GND          |
+------------+      +-------------+
```

The Raspberry Pi Debug Probe also provides a UART (connect its RX to GP0 for the *debug_serial* library).

## Notes and Tips
- The template uses `F_CPU` = 150MHz by default (PLL_SYS from the 12MHz crystal). The peripheral clock and the HSTX clock are the system clock, USB and ADC are clocked with 48MHz by PLL_USB. The tick generators (TICKS) provide the 1us tick for TIMER0, TIMER1 and the watchdog from the 12MHz reference clock.
- All peripherals except GPIO are held in reset after startup and are released by the libraries that use them (`RESET_release()`/`RESET_cycle()` in *system.h*).
- The image definition block (IMAGE_DEF) is included in *system.c* and placed directly behind the vector table by the linker script. It marks the firmware as an executable for the Arm cores in secure mode. Without this block, the boot ROM does not start the firmware.
- The RP2350 has no RTC peripheral. The RTC functions of *system.h* implement a calendar (date, time, weekday, alarm) on the 64-bit millisecond counter of the always-on timer (AON timer) in the power manager (POWMAN), clocked by the crystal oscillator. The AON timer keeps running during all resets except power-on, so `RTC_isInit()` can be checked before `RTC_init()`. The registers of the power manager are password protected (`POWMAN_WRITE()`, `POWMAN_SET()` and `POWMAN_CLR()` in *rp2350.h*).
- After reset, all GPIO pads are isolated (ISO bit). The pin functions of *gpio.h* clear this bit. If a pad register is configured directly, the ISO bit must be cleared as well.
- Code that must run while the flash cannot be accessed (e.g. flash programming) must be placed in SRAM with the `RAM_FUNC` attribute. Time-critical functions can also be placed in SRAM this way.
- Each core has its own NVIC, SysTick and FPU. The functions of *system.h* should only be used by core 0, the *multicore* library starts functions on core 1 (incl. FPU).
- The RP2350 has no open-drain outputs. They can be emulated by switching the pin direction (see *i2c_soft*).
- The watchdog counter of the RP2350 decrements once per 1us tick, the maximum watchdog period is 16.7s. The reset reasons are read from the watchdog and the power manager (`RST_wasXXX()`).
- Erratum RP2350-E9: a GPIO input with the internal pull-down enabled may latch at about 2.2V if it was driven high externally. Use an external pull-down resistor (8.2kOhm or less) if this is a problem. Check the errata list in the datasheet for further limitations.
- Most peripheral registers support atomic set, clear and XOR access via address aliases, which are used by the macros `REG_SET()`, `REG_CLR()`, `REG_XOR()` and `REG_WRITE_MASK()` in *rp2350.h* (not for SIO registers).
- Pins are defined as GP0..GP29 (e.g. `#define PIN_LED GP25`), the pin designators are defined in *system.h*.
