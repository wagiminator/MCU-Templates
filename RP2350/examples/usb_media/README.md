# Raspberry Pi Pico 2 Example: USB Media Keys (usb_media)
## Overview
USB media keys: play/pause, next track and mute with the BOOTSEL button. This example is part of a collection of simple examples for the Raspberry Pi Pico 2. It uses the bare-metal RP2350 template of the [MCU-Templates](https://github.com/wagiminator/MCU-Templates) repository and its libraries, without the Pico SDK, any HAL or IDE. The folder is self-contained: it includes all source files, libraries and the linker script needed for this example. No additional hardware has to be connected, the example only uses the components on the board (LED on GP25, BOOTSEL button, USB, temperature sensor, VSYS measurement on GP29).

## Description
The board appears as a USB media key controller (HID consumer control), no driver is required. The keys control the media player of the PC (or of a smartphone with USB OTG adapter):
- **Short press** of the BOOTSEL button: play/pause (`MEDIA_KEY_SHORT`)
- **Double press**: next track (`MEDIA_KEY_DOUBLE`)
- **Long press** (0.8 s): mute (`MEDIA_KEY_LONG`)

The LED flashes once, twice or long. The keys can be changed in *config.h*, e.g. to volume up/down.

*How it works*: The *hid_consumer* library sends 16-bit consumer control usage codes (play, pause, volume, ...), which are handled by the operating system. *board.c* distinguishes short, long and double presses of the BOOTSEL button with a small state machine.

## Files

| Path | Description |
|:-|:-|
| config.h | **Configuration** of this example: clock, LED pin, example settings, USB descriptors |
| makefile | Compiles and uploads the example |
| src/main.c | the example application |
| src/system.c/.h | template core: startup, clocks, RTC, delay, watchdog, sleep, reset, boot ROM, CRC/DMA |
| src/gpio.h | template core: GPIO, pin interrupts, ADC |
| src/print.c/.h | print functions (printf, numbers, strings) |
| src/millis.c/.h | millisecond counter (TIMER) |
| src/board.c/.h | board support: LED, BOOTSEL button, temperature, VSYS, random number, board info |
| src/rp2350.h | register definitions (CMSIS core and RP2350 peripherals) |
| src/usb_*.c/.h | USB HID consumer control (media keys): USB handler, descriptors, class driver |
| ld/rp2350_4mb.ld | linker script (4MB flash) |
| bin/usb_media.bin | ready-to-flash firmware (binary), compiled with the default config.h |

The libraries in *src* are copies of the RP2350 template and its libraries (*board*, *term* and *shell* are helper libraries of these examples). Library parameters that are not in *config.h* can be changed in the parameter section of the respective header file.

## Configuration
Open *config.h* in a text editor. The settings are:

| Setting | Description |
|:-|:-|
| `F_CPU` | system clock, 150 MHz by default (12 MHz or 24..150 MHz, if exactly generated by the PLL, see system.h) |
| `PIN_LED` | on-board LED (GP25; the LED of the Raspberry Pi Pico 2 W is connected to the WiFi chip and is not supported) |
| `MEDIA_KEY_SHORT` | key for a short press (default play/pause) |
| `MEDIA_KEY_DOUBLE` | key for a double press (default next track) |
| `MEDIA_KEY_LONG` | key for a long press (default mute) |
| `USB_...`, `..._STR` | USB descriptors: vendor/product ID and names shown by the PC |

Note that the USB vendor/product IDs are shared IDs for testing purposes only.

## Compiling and Uploading
### Install Toolchain (Linux)
```
sudo apt install build-essential gcc-arm-none-eabi libnewlib-arm-none-eabi python3 python3-pip
pip install rpprog
```
[rpprog](https://github.com/wagiminator/MCU-Flash-Tools) uploads the firmware via the PICOBOOT interface of the USB bootloader, no drive has to be mounted (on newer Linux distributions, `pipx install rpprog` or a virtual environment may be required). Alternatively, the [xPack ARM GCC](https://xpack-dev-tools.github.io/arm-none-eabi-gcc-xpack/) can be used. rpprog also runs on Windows and macOS (see its README). To use rpprog without root privileges on Linux, grant access to the USB bootloader:
```
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="2e8a", ATTR{idProduct}=="000f", MODE="666"' | sudo tee /etc/udev/rules.d/99-rp2350.rules
sudo udevadm control --reload-rules
```

### Upload via Makefile
Hold the BOOTSEL button while connecting the board to the PC via USB, then release it. Run one of these commands in the folder of the makefile:
```
make flash      compile and upload the example (rpprog)
make all        compile only (bin/usb_media.bin/.hex/.asm)
make clean      remove all build files
```

As this example doesn't have a serial port, the BOOTSEL button must be held while connecting the board for each upload.

### Upload without Toolchain
The folder *bin* contains the firmware of this example, compiled with the default *config.h*. Hold the BOOTSEL button while connecting the board, then run `rpprog -f bin/usb_media.bin` in the folder of the example. The firmware is written, verified and started. Note that `make clean` also removes this file (it is created again by `make flash` or `make bin`).

## Troubleshooting
- **rpprog doesn't find the board**: use a USB cable with data lines, hold BOOTSEL while plugging in (a USB drive named RP2350 appears). On Linux, set the udev rule (see above) or run rpprog with sudo.
- **Nothing happens**: the example only sends reports after the PC has configured the device (wait a second after plugging in). Check the device list of the operating system for the USB HID consumer control (media keys).
- **LED doesn't light up**: the Raspberry Pi Pico 2 W connects the LED to the WiFi chip, which is not supported by the template. Use a Raspberry Pi Pico 2 without WiFi or connect an LED with resistor to another pin and change `PIN_LED`.

## Notes
- The template supports the Arm Cortex-M33 cores of the RP2350 (secure mode).
- Library details are described in the README of the RP2350 template.
