# Raspberry Pi Pico Example: Self Test (self_test)
## Overview
Automatic test of clock, timer, RTC, DMA, flash, both cores, PIO, ADC and PWM. This example is part of a collection of simple examples for the Raspberry Pi Pico. It uses the bare-metal RP2040 template of the [MCU-Templates](https://github.com/wagiminator/MCU-Templates) repository and its libraries, without the Pico SDK, any HAL or IDE. The folder is self-contained: it includes all source files, libraries and the linker script needed for this example. No additional hardware has to be connected, the example only uses the components on the board (LED on GP25, BOOTSEL button, USB, temperature sensor, VSYS measurement on GP29).

## Description
An automatic test of the microcontroller and the template functions. Open the terminal, the tests start automatically:

```
=== Raspberry Pi Pico - Self Test ===
...
 1. System clock ...... 125.0 MHz (expected 125 MHz)  OK
 2. Timer interrupt ... 100 interrupts in 100 ms  OK
 3. Real-time clock ... 2 s in 2.1 s of sleep  OK
 4. CRC / DMA ......... CRC-32 = 0xCBF43926 (expected 0xCBF43926)  OK
 5. Flash ............. JEDEC ID 0xEF4015, 2048 KB, write/read  OK
 6. Dual core ......... FIFO ok, counter 40000 (expected 40000)  OK
 7. PIO ............... invert 0xEDCBA987, reverse 0x1E6A2C48  OK
 8. Temperature ....... 28.4 C  OK
 9. VSYS .............. 4.86 V (USB: approx. 4.7..5.1 V)  OK
10. PWM ............... LED faded in and out  OK

10 of 10 tests passed.
```

| Test | What is tested |
|:-|:-|
| System clock | CPU clock (SysTick) measured against the 1us timer, which is derived from the crystal: PLL and tick generator |
| Timer interrupt | periodic interrupt of the *timer* library (1 ms) |
| Real-time clock | the RTC counts two seconds while the CPU sleeps (`SLEEP_ms()`) |
| CRC / DMA | CRC-32 calculated by the DMA sniffer (`CRC_calc32()`) |
| Flash | JEDEC ID, erase, write and read back the last sector (via boot ROM, *flash* library) |
| Dual core | core 1 answers via the inter-core FIFO; both cores increment a shared counter protected by a spinlock (*multicore* library) |
| PIO | a three-instruction PIO program inverts and bit-reverses data words (*pio* library) |
| Temperature, VSYS | ADC with internal temperature sensor and GP29 (VSYS/3), plausibility check |
| PWM | the LED fades in and out (*pwm* library), the counter must run |

Afterwards, the LED is on if all tests have passed and blinks if a test has failed. Press Enter or the BOOTSEL button to repeat the tests. Type `w` to test the watchdog: it is started and not fed, so the board restarts after one second. Reconnect the terminal, the board information then shows "watchdog" as reason of the last reset. Set `TEST_FLASH` to 0 in *config.h* to skip the flash write test.

## Files

| Path | Description |
|:-|:-|
| config.h | **Configuration** of this example: clock, LED pin, example settings, USB descriptors |
| makefile | Compiles and uploads the example |
| src/main.c | the example application |
| src/system.c/.h | template core: startup, clocks, RTC, delay, watchdog, sleep, reset, boot ROM, CRC/DMA |
| src/gpio.h | template core: GPIO, pin interrupts, ADC |
| src/print.c/.h | print functions (printf, numbers, strings) |
| src/millis.c/.h | millisecond counter (TIMER) |
| src/board.c/.h | board support: LED, BOOTSEL button, temperature, VSYS, random number, board info |
| src/term.c/.h | text input/output via USB serial port (never blocks without terminal) |
| src/timer.c/.h | periodic timer interrupt |
| src/flash.c/.h | flash functions (erase, write, unique ID, JEDEC ID) |
| src/multicore.c/.h | core 1, inter-core FIFO, spinlocks |
| src/pio.h | PIO functions and instruction encoding |
| src/pwm.c/.h | PWM outputs |
| src/rp2040.h | register definitions (CMSIS core and RP2040 peripherals) |
| src/usb_*.c/.h | USB CDC (virtual serial port): USB handler, descriptors, class driver |
| ld/rp2040_2mb.ld | linker script (2MB flash) |
| bin/self_test.bin | ready-to-flash firmware (binary), compiled with the default config.h |

The libraries in *src* are copies of the RP2040 template and its libraries (*board*, *term* and *shell* are helper libraries of these examples). Library parameters that are not in *config.h* can be changed in the parameter section of the respective header file.

## Configuration
Open *config.h* in a text editor. The settings are:

| Setting | Description |
|:-|:-|
| `F_CPU` | system clock, 125 MHz by default (12 MHz or 16..133 MHz, if exactly generated by the PLL, see system.h) |
| `PIN_LED` | on-board LED (GP25; the LED of the Raspberry Pi Pico W is connected to the WiFi chip and is not supported) |
| `TEST_FLASH` | 1: erase/write test of the last flash sector, 0: skip |
| `USB_...`, `..._STR` | USB descriptors: vendor/product ID and names shown by the PC |

Note that the USB vendor/product IDs are shared IDs for testing purposes only.

## Compiling and Uploading
### Install Toolchain (Linux)
```
sudo apt install build-essential gcc-arm-none-eabi libnewlib-arm-none-eabi python3 python3-pip
pip install rpprog
```
[rpprog](https://github.com/wagiminator/MCU-Flash-Tools) uploads the firmware via the PICOBOOT interface of the USB bootloader, no drive has to be mounted (on newer Linux distributions, `pipx install rpprog` or a virtual environment may be required). Alternatively, the [xPack ARM GCC](https://xpack-dev-tools.github.io/arm-none-eabi-gcc-xpack/) can be used. rpprog also runs on Windows and macOS (see its README). To use rpprog without root privileges on Linux, grant access to the USB bootloader:
```
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="2e8a", ATTR{idProduct}=="0003", MODE="666"' | sudo tee /etc/udev/rules.d/99-rp2040.rules
sudo udevadm control --reload-rules
```

### Upload via Makefile
For the first upload, hold the BOOTSEL button while connecting the board to the PC via USB, then release it. Afterwards, `make flash` restarts the running example into the USB bootloader automatically via its USB serial port (`rpprog -b`), so the BOOTSEL button is no longer needed. Run one of these commands in the folder of the makefile:
```
make flash      compile and upload the example (rpprog)
make monitor    open serial monitor (exit with CTRL-])
make reboot     restart into USB bootloader (rpprog -b)
make all        compile only (bin/self_test.bin/.hex/.asm)
make clean      remove all build files
```

### Upload without Toolchain
The folder *bin* contains the firmware of this example, compiled with the default *config.h*. Hold the BOOTSEL button while connecting the board, then run `rpprog -f bin/self_test.bin` in the folder of the example. The firmware is written, verified and started. Note that `make clean` also removes this file (it is created again by `make flash` or `make bin`).

### Serial Terminal
The board appears as a USB serial port (Linux: */dev/ttyACM0*, Windows: COMx, macOS: */dev/cu.usbmodem...*). Any terminal program can be used, the baud rate doesn't matter (e.g. `make monitor` with pyserial installed, PuTTY, the Arduino serial monitor, or a web serial terminal in Chrome). The example starts its output when the terminal opens the port.

## Hardware Test
As the examples are also meant to test the template on real hardware, here is what to check:

| What to check | Tested functions |
|:-|:-|
| All 10 tests pass, `w` resets the board and the reason 'watchdog' is shown | clock/PLL, tick generator, SysTick, timer, RTC, sleep, DMA/CRC, flash, multicore, spinlocks, PIO, ADC, PWM, watchdog |

## Troubleshooting
- **rpprog doesn't find the board**: use a USB cable with data lines, hold BOOTSEL while plugging in (a USB drive named RPI-RP2 appears). On Linux, set the udev rule (see above) or run rpprog with sudo.
- **No serial port / no output**: the welcome message or test results are sent when the terminal opens the port; close and reopen the terminal. Some terminal programs don't set DTR - enable DTR in the settings.
- **LED doesn't light up**: the Raspberry Pi Pico W connects the LED to the WiFi chip, which is not supported by the template. Use a Raspberry Pi Pico without WiFi or connect an LED with resistor to another pin and change `PIN_LED`.
