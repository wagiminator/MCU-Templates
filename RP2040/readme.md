# MCU Template for RP2040 Microcontrollers (Raspberry Pi Pico)
## Overview
The RP2040 from Raspberry Pi is a 32-bit microcontroller with two Arm® Cortex®-M0+ cores running at up to 133MHz. It has 264KB of on-chip SRAM, no internal flash and executes code from an external QSPI flash memory (execute in place, XIP, with 16KB cache). The I/O supply voltage is 1.8V to 3.3V, the core voltage of 1.1V is generated by an internal regulator. The chip has the following peripherals:
- two UARTs, two SPI controllers and two I2C controllers
- 16 PWM channels (8 slices with two outputs each)
- a 12-bit ADC (500ksps, 4 inputs and internal temperature sensor)
- two programmable I/O blocks (PIO) with 4 state machines each, which can implement almost any digital interface (e.g. WS2812, I2S, VGA, additional UARTs)
- a USB 1.1 full-speed controller with PHY (device and host mode)
- a 64-bit microsecond timer with 4 alarms, a real-time clock (RTC) and a watchdog
- a 12-channel DMA controller, interpolators and integer dividers per core
- a crystal oscillator (XOSC), a ring oscillator (ROSC) and two PLLs

The boot ROM contains a USB bootloader (BOOTSEL mode), which appears as a mass storage device (RPI-RP2 drive) for UF2 files and as a PICOBOOT interface (used by rpprog and picotool). It is started by holding the BOOTSEL button (flash chip select pulled low) during reset or power-up, or by the firmware.

This template is a lightweight starting point for bare-metal firmware development in C without the Raspberry Pi Pico SDK, any HAL or IDE. It contains:
- a makefile
- linker scripts
- a second stage bootloader (boot2), startup code and system configuration
- basic GPIO, pin interrupt and ADC functions
- an example program

Optional libraries for the internal peripherals are also included.

## Supported Microcontrollers and Boards

| Device / Board | Flash | Crystal | LED | Linker Script | boot2 (SYS_BOOT2) |
|:-|-:|:-:|:-:|:-|:-|
| Raspberry Pi Pico, Pico H | 2MB (W25Q16JV) | 12MHz | GP25 | ld/rp2040_2mb.ld | 0: W25Q080 |
| Raspberry Pi Pico W | 2MB (W25Q16JV) | 12MHz | (WiFi chip) | ld/rp2040_2mb.ld | 0: W25Q080 |
| Waveshare RP2040-Zero | 2MB (W25Q16JV) | 12MHz | WS2812 (GP16) | ld/rp2040_2mb.ld | 0: W25Q080 |
| Seeed XIAO RP2040 | 2MB | 12MHz | GP25 | ld/rp2040_2mb.ld | 0: W25Q080 |
| Other boards with Winbond W25Qxx flash | 2..16MB | 12MHz | - | ld/rp2040_<size>.ld | 0: W25Q080 |
| Boards with other flash chips | 2..16MB | 12MHz | - | ld/rp2040_<size>.ld | 1: generic |

The flash size is selected in the *makefile* (`LDSCRIPT`), the second stage bootloader in *system.h* (`SYS_BOOT2`). The W25Q080 boot2 (quad SPI, continuous read mode) works with the Winbond W25Qxx flash chips, the generic boot2 (standard SPI read command 03h) works with any 25-series flash, but is slower. The template assumes a 12MHz crystal (`XOSC_VALUE` in *rp2040.h*), which is used by all common boards. Check the documentation of your board for the flash chip and the LED pin.

Common features:
- Dual Arm® Cortex®-M0+ cores, up to 133MHz (overclocking is possible, but not supported by the template)
- 264KB SRAM in six banks (4 x 64KB striped, 2 x 4KB), 16KB boot ROM, 16KB XIP cache
- 30 GPIOs (GP0..GP29, GP26..GP29 with ADC), dedicated USB pins (USB_DP/USB_DM), serial wire debug (SWCLK, SWDIO, multi-drop)
- 64-bit unique ID of the external flash chip (used as board ID)

The Raspberry Pi Pico has a 3-pin debug header (SWCLK, GND, SWDIO), the BOOTSEL button and the RUN pin (pin 30, reset when pulled low). The ADC reference is the 3.3V supply (ADC_VREF on pin 35).

## Template Structure

| Path | Description |
|:-|:-|
| template/makefile | Makefile for compiling and uploading (GCC ARM toolchain, rpprog, OpenOCD) |
| template/ld/ | Linker scripts for 2/4/8/16MB flash (boot2, vector table at 0x10000100, SRAM 264KB) |
| template/src/main.c | Example program (blinking LED on GP25) |
| template/src/system.c/h | boot2, startup code, vector table, pin designators, clock (XOSC, PLLs), RTC, delay, watchdog, sleep/dormant, reset, bootloader, boot ROM, CRC, DMA and interrupt functions |
| template/src/gpio.h | GPIO, pin interrupt and ADC functions (incl. temperature sensor) |
| template/src/rp2040.h | Register definitions (CMSIS core and RP2040 peripherals, generated from the SVD file of the Pico SDK) |
| libraries/ | Optional libraries for internal peripherals (see below) |
| datasheet/ | Links to the datasheets |

## Libraries
The *libraries* folder contains optional libraries for the internal peripherals. To use a library, copy the corresponding *.c* and *.h* files into the *src* folder of the template and include the header file in your program. Parameters such as pins, baud rate or clock rate can be set in the parameter section at the beginning of the respective header file. Libraries that use the same peripheral (e.g. *uart* and *debug_serial* on the same UART, or *spi* and *spi_dma*) must not be used at the same time.

| Library | Description |
|:-|:-|
| debug_serial | Serial debug output (UART, TX only) with simple printf, for debugging |
| flash | Flash memory functions (via boot ROM): erase sectors, write pages/words, user data at the end of the flash, unique ID and JEDEC ID of the flash chip |
| i2c | I2C master functions (I2C0/I2C1, polling) |
| i2c_soft | Software I2C master (bit-banging) on any pins |
| millis | Millisecond and microsecond counter using the 64-bit TIMER (no interrupt) |
| multicore | Start functions on core 1, inter-core FIFO and spinlocks |
| neo_pio | NeoPixel (WS2812) control using a PIO state machine (any pin) |
| pio | PIO functions: load programs, configure and control state machines, instruction encoding |
| print | Print functions (printf, numbers, strings) for the serial and other libraries |
| pwm | PWM outputs on any pin (8 slices, 16 channels) |
| spi | SPI master functions (SPI0/SPI1) |
| spi_dma | SPI master functions with DMA (background transfers of buffers) |
| spi_soft | Software SPI master (bit-banging) on any pins |
| timer | Periodic timer interrupt (TIMER alarm 0) |
| uart | Basic UART functions (UART0/UART1, polling, no buffer) |
| uart2 | Second UART (copy of uart with prefix `UART2_`, default UART1) |
| usb/usb_cdc | USB CDC (virtual serial port), with 1200 baud touch to enter the USB bootloader |
| usb/hid_keyboard | USB HID keyboard |
| usb/hid_mouse | USB HID mouse |
| usb/hid_consumer | USB HID consumer control (media keys) |
| usb/hid_composite | USB HID composite device (keyboard, mouse and consumer control) |

The USB libraries consist of several files (all files of the respective folder must be copied into the *src* folder). The USB device descriptors and strings are set in *config.h*. The USB libraries have the same structure and API as the USB libraries of the ATSAMD21, CH32X035 and ATSAMD11 templates (device mode only): only the USB handler (*usb_handler.c*) is specific to the RP2040, the class drivers are identical. The USB controller is clocked with 48MHz by PLL_USB, independent of `F_CPU`. Note that the VID/PID in *config.h* are shared IDs for testing purposes only.

The functions of the clock system, RTC, watchdog, sleep modes, DMA, CRC (DMA sniffer) and boot ROM are part of *system.h*. The GPIO, pin interrupts and the ADC are part of *gpio.h*. The interpolators, the hardware dividers, the USB host mode and PIO programs other than WS2812 are not covered by the libraries, but can be used directly via the register definitions in *rp2040.h* (and the *pio* library).

## Compiling Firmware
To use the *makefile*, some additional software components must be installed to set up the toolchain.

### Install GCC Toolchain for Compiling
```
sudo apt install build-essential gcc-arm-none-eabi libnewlib-arm-none-eabi
```

### Install Python3 and Programming Tools
```
sudo apt install python3 python3-pip
pip install rpprog
```
[rpprog](https://github.com/wagiminator/MCU-Flash-Tools) uploads the binary file via the PICOBOOT interface of the USB bootloader (no drive has to be mounted). On newer Linux distributions, `pipx install rpprog` or a virtual environment may be required. To use rpprog without root privileges, grant access permissions to the USB bootloader:
```
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="2e8a", ATTR{idProduct}=="0003", MODE="666"' | sudo tee /etc/udev/rules.d/99-rp2040.rules
sudo udevadm control --reload-rules
```

### Compiling/Uploading
Edit the *makefile* according to the needs of the project (e.g. `F_CPU`, `LDSCRIPT`). Use one of the following commands inside the *template* folder to compile/upload:

```
make all       compile and build <firmware>.elf/.bin/.hex/.asm
make hex       compile and build <firmware>.hex
make asm       compile and disassemble to <firmware>.asm
make bin       compile and build <firmware>.bin
make flash     compile and upload to MCU (USB bootloader, rpprog)
make flash-swd compile and upload to MCU via SWD (CMSIS-DAP, OpenOCD)
make reboot    reboot MCU into USB bootloader (only if usb_cdc is used)
make clean     remove all build files
```

Supported values for `F_CPU`: 12MHz (crystal oscillator without PLL) and 16MHz to 133MHz, if the frequency can be generated exactly by the PLL, e.g. 133, 125 (default), 120, 100, 96, 72, 64, 50, 48, 36, 32, 24 and 16MHz.

## Uploading Firmware
### Via USB Bootloader (BOOTSEL Mode)
Hold the BOOTSEL button while connecting the board to the PC via USB (or while pressing the RESET/RUN button, if available), then release the button. The RP2040 appears as a mass storage device named RPI-RP2 and as a PICOBOOT device.
- **rpprog**: `make flash` uploads the binary file with [rpprog](https://github.com/wagiminator/MCU-Flash-Tools) (`rpprog -b -f bin/<firmware>.bin`). The firmware is written, verified and started. rpprog also accepts UF2, HEX and ELF files.
- **From the firmware**: `BOOT_now()` restarts the RP2040 into the USB bootloader. With the *usb_cdc* library, the bootloader is also entered when the host opens the serial port with 1200 baud and closes it again. `rpprog -b` does this automatically (`make flash`, or `make reboot` to only restart into the bootloader), so the BOOTSEL button is not needed for further uploads.
- **Drag and drop**: The RPI-RP2 drive only accepts UF2 files. If needed, the binary file can be converted with picotool, e.g. `picotool uf2 convert bin/<firmware>.bin <firmware>.uf2 -o 0x10000000 --family rp2040`, and then copied to the drive.

### Via Serial Wire Debug Interface (SWD)
Connect an SWD programmer that supports the multi-drop SWD of the RP2040 (e.g. Raspberry Pi Debug Probe or Picoprobe) to the SWCLK, SWDIO and GND pins of the debug header. `make flash-swd` uploads the firmware via [OpenOCD](https://openocd.org/) (version 0.12 or newer, target *rp2040.cfg*).

```
SWD Programmer      RP2040 / Pico
+------------+      +-------------+
|       SWCLK| ---> |SWCLK        |
|       SWDIO| <--> |SWDIO        |
|         GND| ---> |GND          |
+------------+      +-------------+
```

The Raspberry Pi Debug Probe also provides a UART (connect its RX to GP0 for the *debug_serial* library).

## Notes and Tips
- The template uses `F_CPU` = 125MHz by default (PLL_SYS from the 12MHz crystal). The peripheral clock is the system clock, USB and ADC are clocked with 48MHz by PLL_USB, the RTC with 46875Hz. The 1us tick for the TIMER and the watchdog is generated from the 12MHz reference clock.
- All peripherals except GPIO are held in reset after startup and are released by the libraries that use them (`RESET_release()`/`RESET_cycle()` in *system.h*).
- The second stage bootloader (boot2) is included in *system.c* as a pre-assembled array (assembled from the Pico SDK sources, incl. the checksum required by the boot ROM). It configures the flash interface for fast XIP and starts the firmware.
- Code that must run while the flash cannot be accessed (e.g. flash programming) must be placed in SRAM with the `RAM_FUNC` attribute. Time-critical functions can also be placed in SRAM this way.
- Each core has its own NVIC and SysTick. The functions of *system.h* should only be used by core 0, the *multicore* library starts functions on core 1.
- The RP2040 has no open-drain outputs. They can be emulated by switching the pin direction (see *i2c_soft*).
- The watchdog counter of the RP2040 decrements twice per tick (erratum RP2040-E1), the maximum watchdog period is 8.3s.
- Most peripheral registers support atomic set, clear and XOR access via address aliases, which are used by the macros `REG_SET()`, `REG_CLR()`, `REG_XOR()` and `REG_WRITE_MASK()` in *rp2040.h* (not for SIO registers).
- Pins are defined as GP0..GP29 (e.g. `#define PIN_LED GP25`), the pin designators are defined in *system.h*.
